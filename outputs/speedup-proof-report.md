## What changed

Replaced 32 per-byte String(format:) calls per SHA-256 digest with direct lowercase UTF-8 hexadecimal encoding through a fixed lookup table. The stable teardown repair was applied before both benchmark sides and is not part of the measured production transformation.

**Why behavior remains equivalent:** Each hash byte still emits its upper nibble followed by its lower nibble using the same lowercase hexadecimal alphabet; a hardcoded known vector and the existing GraphDataStore behavioral suite verify exact output and downstream behavior.

| Complexity | Before | After |
|---|---:|---:|
| Estimate | O(h) with 32 formatter-created strings per digest | O(h) with one reserved 64-byte buffer per digest |

## Limitations

- The benchmark measures the complete user-visible renderer path; it does not isolate GraphDataStore digest time as a standalone microbenchmark.
- RSS samples cover only the app test process, not WebKit helper processes.
- Offline 2D remains intentionally outside the supported boundary because BrainBar does not vendor Vis.js.

## Residual risks

- Any future digest implementation must retain the exact lowercase 64-character representation because it versions snapshots and layout-cache URLs.
- Hosted WKWebView measurements remain environment-sensitive even though the explicit blank-page teardown removed the reproduced deinit failure.
